<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: UAT — Dream Goal end-to-end on device</name>
  <what-built>
    Phase 4 Dream Goal screen: empty state first-save flow, view mode with motivational framing, edit flow via pencil icon, persistence across app restart, Cancel discard behavior, character counter near limit, disabled Save button when unchanged, no guilt language anywhere.
  </what-built>
  <how-to-verify>
    Start the app: npx expo start (or your EAS dev build). Navigate to the Goal tab (rightmost tab in the bottom nav).

    --- Scenario A: Empty state + first save (GOAL-01, GOAL-02) ---
    1. Clear any existing dream goal: in the Expo dev menu or by reinstalling, or manually run `DELETE FROM dream_goal;` via Drizzle Studio if available.
    2. Open Goal tab. Expected: TextInput is immediately visible and focused (no extra tap required). Motivational copy "You're building your dream one win at a time." appears ABOVE the TextInput.
    3. Without typing anything: confirm Save button is visually dimmed (opacity-50). Do NOT tap it.
    4. Type "Run a marathon in under 4 hours". Confirm Save button becomes active (full opacity, orange).
    5. Tap Save Goal. Expected: view mode appears with "Run a marathon in under 4 hours" as large hero text. Motivational copy now appears BELOW the goal card.
    6. Confirm no error message is visible.

    --- Scenario B: Persistence (GOAL-01) ---
    7. Force-quit the app completely (swipe away from app switcher on iOS; recent apps on Android).
    8. Relaunch and navigate to Goal tab. Expected: "Run a marathon in under 4 hours" still appears in view mode — goal survived the restart.

    --- Scenario C: Edit flow (GOAL-03) ---
    9. From view mode, tap the pencil icon (top-right). Expected: editor appears with "Run a marathon in under 4 hours" pre-loaded in the TextInput. Pencil icon disappears.
    10. Without changing text: Save button is dimmed (no change = Save disabled per D-06).
    11. Append " — Boston 2027" to the goal text. Save button becomes active.
    12. Tap Save Goal. Expected: view mode shows "Run a marathon in under 4 hours — Boston 2027" as hero text. Edit completed.

    --- Scenario D: Cancel flow (GOAL-03, D-02) ---
    13. Tap pencil icon again to enter edit mode.
    14. Clear all text and type "something completely different".
    15. Tap Cancel. Expected: edit mode closes immediately (no confirmation dialog). View mode shows "Run a marathon in under 4 hours — Boston 2027" — the Cancel change was silently discarded.

    --- Scenario E: Character counter (GOAL-01, D-07) ---
    16. Tap pencil icon to enter edit mode. Clear text.
    17. Type or paste 400 characters (exactly). Confirm NO counter is visible yet (401 remaining > 100).
    18. Type 1 more character (401 total, 99 remaining). Confirm counter NOW appears showing "99 / 500".
    19. Keep typing. At 500 characters confirm counter shows "0 / 500". Confirm TextInput rejects further input (maxLength enforced).
    20. Tap Cancel to discard.

    --- Scenario F: No guilt language audit ---
    21. Review all visible copy on the Goal screen in each state (empty, view, edit). Confirm zero guilt/shame/punishment language. "You're building your dream one win at a time." — pass. "What are you working toward?" placeholder — pass. "Save Goal" — pass. "Cancel" — pass.
    22. Trigger the save error state if possible (disconnect SQLite, or deliberately corrupt — optional). If the error appears, confirm "Couldn't save your goal — tap Save Goal to try again." is encouraging and action-oriented, not blaming.

    --- Tab navigation ---
    23. Navigate to other tabs (Home, Wins, Settings) and back to Goal. Confirm the goal screen still shows the correct state without flickering or losing content.
  </how-to-verify>
