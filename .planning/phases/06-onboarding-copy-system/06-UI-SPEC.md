# Phase 6 — UI Design Contract

> Visual and interaction contract for the Onboarding + Copy System phase.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Platform note:** React Native / Expo app. All styling uses NativeWind v4
> `className` utilities on React Native primitives. No shadcn, no web DOM, no
> HTML elements. StyleSheet.create is prohibited in new components — use
> NativeWind className except for tiny React Native style props that existing
> components already require, such as image dimensions.

| Property | Value | Source |

## Spacing Scale

Inherited from prior phases. Multiples of 4 only; Tailwind class names are the implementation contract.

| Token | Value | Tailwind class | Usage |
|-------|-------|----------------|-------|
| xs | 4px | `p-1` / `gap-1` / `m-1` | Icon gaps, tiny inline spacing |
| sm | 8px | `p-2` / `gap-2` / `m-2` | Compact field and banner inner gaps |
| md | 16px | `p-4` / `px-4` / `gap-4` | Default screen horizontal padding, card padding |
| lg | 24px | `p-6` / `py-6` / `gap-6` | Onboarding card vertical padding, banner padding |
| xl | 32px | `p-8` / `mt-8` / `mb-8` | Trophy-to-copy gap, major block separation |
| 2xl | 48px | `p-12` / `mt-12` | Welcome hero breathing room |
| 3xl | 64px | `p-16` | Reserved; avoid unless a screen needs large top balance |

**Exceptions:**
- Touch targets: all tappable buttons and icon controls must be at least 44px high and 44px wide using `min-h-[44px] min-w-[44px]` where applicable.
- Welcome trophy image: 132px square. This is an image dimension, not layout spacing.
- Home post-win banner icon: 20px. This is icon sizing, not spacing.
- Goal TextInput minimum height remains 120px, inherited from `GoalEditor`.

## Typography

Use the established 4-size, 2-weight app scale. Do not introduce new font sizes or active weights.

| Role | Size | Weight | Line Height | NativeWind class | Usage |
|------|------|--------|-------------|------------------|-------|
| Body | 16px | 400 regular | 1.5 | `font-nunito-regular text-base leading-relaxed` | Supporting copy, input text, banner body |
| Label | 14px | 700 bold | 1.4 | `font-nunito-bold text-sm leading-snug` | Button labels, small captions, character counter |
| Heading | 20px | 700 bold | 1.2 | `font-nunito-bold text-xl leading-tight` | Screen section titles, banner title |
| Display | 28px | 700 bold | 1.2 | `font-nunito-bold text-[28px] leading-tight` | Welcome headline, onboarding Dream Goal headline |

**Active weights:** 400 regular and 700 bold only. Do not use 600, 800, or 900 in Phase 6 UI.

Text must not scale with viewport width. Use natural wrapping with constrained widths, never negative letter spacing.

## Screen Layout Contract

### Root Onboarding Gate (`app/_layout.tsx`)

The root layout must not show tabs while onboarding state is unknown.

```
Splash / null while:
  migrations/fonts not ready
  OR onboarding_completed read is pending

If onboarding_completed !== "true":
  replace route with /onboarding/welcome

If onboarding_completed === "true":
  render normal Stack with (tabs)
```

Rules:
- Read `onboarding_completed` only after database migrations and fonts are ready.
- Use `router.replace(...)` for onboarding redirects to avoid back navigation into onboarding.
- Keep notification AppState top-up logic unchanged and active only after root readiness.
- Do not request notification permission during onboarding.

### Welcome Screen (`app/onboarding/welcome.tsx`)

Primary focal point: trophy image first, headline second, `Start Winning` CTA third.

```
SafeAreaView bg-background flex-1
  View flex-1 px-6 items-center justify-center
    Image trophy.png                132x132, resizeMode="contain", mb-8
    Text headline                   Display, text-primary, text-center, max-w-[320px]
    Text support                    Body, text-secondary, text-center, mt-4, max-w-[320px]
    Pressable Start Winning         bg-primary rounded-lg min-h-[44px] px-6 mt-8
```

Locked copy:
- Headline: `"Welcome to Winning Streak"`
- Support: `"Log one small win at a time and build proof that you're already moving."`
- Primary CTA: `"Start Winning"`

Interaction:
- Tapping `Start Winning` routes with `router.replace("/onboarding/dream-goal")`.
- No Skip button on Welcome. Skip applies only to Dream Goal setup.
- No tabs, tab bar, Settings links, or notification prompts appear here.

Accessibility:
- Trophy image: `accessibilityLabel="Winning Streak trophy"`
- CTA: `accessibilityRole="button"`, `accessibilityLabel="Start Winning"`

### Onboarding Dream Goal Screen (`app/onboarding/dream-goal.tsx`)

Primary focal point: headline and input. Secondary path: `Skip for now`, visible but quiet.

```
SafeAreaView bg-background flex-1
  KeyboardAvoidingView flex-1
    ScrollView px-4 contentContainerStyle paddingBottom: 32
      Text headline                  Display, text-primary, text-center, mt-8
      Text support                   Body, text-secondary, text-center, mt-3 mb-6

      View editor card               bg-surface rounded-xl px-4 py-4 border border-border
        TextInput multiline          minHeight 120, maxLength 500
        Text counter                 Label, text-secondary, visible when <=100 chars remain

      Pressable Save Goal            bg-primary rounded-lg min-h-[44px] mt-4
      Pressable Skip for now         min-h-[44px] mt-2, transparent

      [success state if saved]
        Text success                 Body, text-secondary, text-center, mt-4
```

Locked copy:
- Headline: `"Set a Dream Goal"`
- Support: `"Optional, but powerful: name what your wins are building toward."`
- Placeholder: `"What are you working toward?"`
- Primary CTA: `"Save Goal"`
- Secondary CTA: `"Skip for now"`
- Success copy: `"Saved. Let's log your first win."`
- Save error: `"Couldn't save your goal — tap Save Goal to try again."`

Interaction:
- `Save Goal` disabled until `validateGoalText(currentText)` is true.
- Save path: `upsertGoal(currentText.trim())` -> `setSetting("onboarding_completed", "true")` -> show success copy briefly -> `router.replace("/(tabs)")` or Home route equivalent.
- Skip path: `setSetting("onboarding_completed", "true")` -> `router.replace("/(tabs)")` or Home route equivalent.
- Skip must not write an empty Dream Goal.
- Save failure keeps the user's text in place and shows the inline error copy.
- No Cancel button; this is a first-run setup screen, not an edit mode.

Accessibility:
- TextInput: `accessibilityLabel="Dream Goal text"`, `accessibilityHint="Type your dream goal, up to 500 characters"`
- Save: `accessibilityRole="button"`, `accessibilityLabel="Save Goal"`, `accessibilityState={{ disabled: !canSave }}`
- Skip: `accessibilityRole="button"`, `accessibilityLabel="Skip Dream Goal setup for now"`

### Home Post-Win Banner (`app/(tabs)/index.tsx` + `PostWinBanner`)

Primary focal point remains the Home win-entry loop. Banners must not block the input area or turn Home into a celebratory modal.

Placement:
- Render below `StreakHeader` and above the empty/populated wins region.
- Banner is Home-only and tied to the just-saved win.
- Banner may auto-dismiss after a short duration or be manually dismissible with an icon button. If dismissible, icon button uses Ionicons `close-outline`, 44x44 target, and `accessibilityLabel="Dismiss message"`.

Layout:

```
View mx-4 mt-3 mb-1 bg-surface rounded-xl border border-border overflow-hidden
  View flex-row
    View w-1 bg-primary
    View flex-1 px-4 py-3
      Text title          Heading, text-primary
      Text body           Body, text-secondary, mt-1
    [optional close icon] min-h-[44px] min-w-[44px]
```

Visual rules:
- Use `bg-primary` rail for milestone/comeback/first-win banners.
- Use `text-gold` only for a small trophy/star icon if included; do not add decorative confetti or background blobs.
- No full-width modal, toast overlay, or blocking sheet.
- Banner height must be content-driven but stable enough not to cover `WinInputArea`.

Moment priority:
1. First win ever
2. Exact streak milestone 7, 30, or 100
3. Comeback after a date-key gap greater than one calendar day
4. Generic post-save/session-complete moment

## Copywriting Contract

### Onboarding copy

| Element | Copy |
|---------|------|
| Welcome headline | "Welcome to Winning Streak" |
| Welcome support | "Log one small win at a time and build proof that you're already moving." |
| Welcome primary CTA | "Start Winning" |
| Dream Goal headline | "Set a Dream Goal" |
| Dream Goal support | "Optional, but powerful: name what your wins are building toward." |
| Dream Goal placeholder | "What are you working toward?" |
| Dream Goal primary CTA | "Save Goal" |
| Dream Goal secondary CTA | "Skip for now" |
| Dream Goal success | "Saved. Let's log your first win." |
| Dream Goal save error | "Couldn't save your goal — tap Save Goal to try again." |

### Home banner copy states

The copy catalog must provide at least these states. Exact variant arrays may expand to 3-5 variants, but every variant must preserve the tone below.

| State | Title | Body |
|-------|-------|------|
| First win ever | "First win logged" | "That's the whole move. Notice one win, then come back tomorrow." |
| 7-day milestone | "7 days of wins" | "A full week of noticing what is working. Keep building." |
| 30-day milestone | "30 days strong" | "That's a real rhythm. Your wins are starting to stack." |
| 100-day milestone | "100 days of proof" | "You have built something rare. One win at a time." |
| Comeback | "You're back in motion" | "Today counts. Start from this win and keep going." |
| Generic post-save | "Win added" | "One more piece of proof that you're moving." |
| Long streak | "{n} day streak" | "You're building something real." |

### Catalog coverage requirements

The central typed copy catalog must cover:
- first win ever
- 7, 30, and 100 day milestones
- comeback after a miss
- generic post-save/session-complete moment
- long streak
- Home empty state
- History empty state
- Dream Goal empty state
- notification disabled notice
- save/load errors
- notification prompt variants

### No-guilt invariant

Forbidden language in emotional states includes: `missed`, `forgot`, `failed`, `failure`, `broke`, `broken`, `lost`, `punish`, `shame`, `guilt`, `sorry`, `oops`, `should have`, `don't break`.

Exception: internal test names and developer comments may mention banned words only when documenting the invariant. User-facing strings must not.

No destructive actions exist in Phase 6.

## Interaction Contract

### Onboarding completion

| Trigger | Required behavior |
|---------|-------------------|
| Welcome CTA | `router.replace("/onboarding/dream-goal")` |
| Dream Goal Save | Validate text -> save goal -> write `onboarding_completed=true` -> success state -> Home |
| Dream Goal Skip | Write `onboarding_completed=true` -> Home |
| App relaunched before completion | Onboarding resumes because `onboarding_completed` was not written |
| App relaunched after completion | Onboarding never shows again |

### Post-win banner

| Trigger | Required behavior |
|---------|-------------------|
| First saved win ever | Show first-win banner after save completes |
| Save reaches streak 7/30/100 | Show milestone banner immediately after save completes |
| Save follows date-key gap > 1 day | Show comeback banner immediately after save completes |
| Normal save | Show generic post-save banner or no banner; if shown, it must be small and non-blocking |
| Banner dismissed | Remove only the current Home banner; do not persist dismissal |

### Copy determinism

- Variant selection must be deterministic by date key, streak, win count, or explicit seed.
- The same app state must not flicker between variants during a render cycle.
- Notification prompt copy remains deterministic by `date_key`.

## State Machines

### Root Layout

| State | Condition | UI |
|-------|-----------|----|
| `booting` | fonts/migrations not ready | `null`, splash remains |
| `checking-onboarding` | app ready, settings read pending | `null`, no tabs flash |
| `needs-onboarding` | `onboarding_completed !== "true"` | replace to Welcome route |
| `ready` | `onboarding_completed === "true"` | normal Stack with `(tabs)` |
| `error` | migrations error | log error; preserve existing failure behavior |

### Onboarding Dream Goal

| State | Trigger | UI |
|-------|---------|----|
| `editing` | route mounted | headline, support, editor, Save Goal, Skip for now |
| `saving` | Save pressed | Save disabled/opacity-50; input preserved |
| `saved` | `upsertGoal` and setting write succeed | success copy briefly visible, then Home replace |
| `skipping` | Skip pressed | Skip disabled/opacity-50, then Home replace |
| `error` | save fails | same editing UI plus inline save error |

### Home Banner

| State | Trigger | UI |
|-------|---------|----|
| `hidden` | no current post-win moment | no banner |
| `visible` | moment detected after save | `PostWinBanner` below `StreakHeader` |
| `dismissed` | close/timer | no banner until next saved win |
