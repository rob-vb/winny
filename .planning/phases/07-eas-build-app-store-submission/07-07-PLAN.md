<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 1: App Store review outcome + iOS production go-live</name>

  <what-built>
  The iOS app was submitted for App Store review in Plan 06. Apple review typically takes 1–3 business days. This task waits for the outcome and handles the two possible results: approved or rejected.
  </what-built>

  <how-to-verify>
  Wait for the App Store review result. Apple sends an email and updates the status in App Store Connect.

  Outcome A — APPROVED ("Ready for Sale" or "Pending Developer Release"):
    1. In App Store Connect, click "Release to App Store" (if manual release was set) or confirm automatic release is live
    2. Confirm the App Store listing is publicly accessible:
       curl -I https://apps.apple.com/app/winny/id<ascAppId>
       Expected: HTTP 200 (may take up to 24h after approval for the page to appear)
    3. On an iPhone NOT enrolled in TestFlight for this app: search "Winny" in the App Store
    4. Install from the App Store (not TestFlight)
    5. Final fresh-install smoke test:
       a. Onboarding appears → 3 taps max to first win entry screen
       b. Log one win → notification permission dialog appears (NOT on cold launch)
       c. Settings → all three sections work
    Report: "iOS live — App Store URL: https://apps.apple.com/app/winny/id<ascAppId>"

  Outcome B — REJECTED:
    1. Read the rejection reason in App Store Connect → Resolution Center
    2. Common causes and fixes:
       - NOTF-01 wrong timing: verify notificationService.ts permission request is inside addWin(), not in _layout.tsx or root init
       - Privacy policy 404: re-verify curl -I <PRIVACY_URL> returns 200
       - Crash on reviewer device: check crash log in Xcode Organizer or App Store Connect → Crashes
       - Metadata/screenshot issue: address the specific feedback
    3. Fix the issue, create a new EAS production build if code changes needed:
       eas build --platform ios --profile production --non-interactive
       eas submit --platform ios --profile production --latest
    4. Resubmit for review in App Store Connect
  </how-to-verify>

  <resume-signal>Type "iOS live" with the App Store URL, or describe the rejection reason if rejected.</resume-signal>
</task>

<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Google Play review outcome + Android production go-live</name>

  <what-built>
  The Android app was either submitted for direct production review (no tester gate) or is in the 14-day closed testing period (tester gate applies) — per Plan 06 Task 3.
  </what-built>

  <how-to-verify>
  Case A — No tester gate (account before Nov 13, 2023):
    Wait for Google Play review (typically 3–7 days). Google sends email and updates Play Console status.
    Approved:
      1. In Play Console → Production → confirm status "Available on Google Play"
      2. Verify Play Store listing publicly accessible:
         curl -I "https://play.google.com/store/apps/details?id=com.robvb.winny"
         Expected: HTTP 200
      3. On an Android device (not a test device from internal testing): search "Winny" in Google Play
      4. Install and run smoke test (same 3 steps as iOS smoke test)
      Report: "Android live — Play Store URL: https://play.google.com/store/apps/details?id=com.robvb.winny"
    Rejected:
      Read rejection reason in Play Console → Policy → Policy status. Address and resubmit.
      For Android resubmit: eas submit --platform android --profile production --latest

  Case B — Tester gate applies (account after Nov 13, 2023):
    First sub-task: confirm 12 testers are opted in and 14 continuous days have passed.
      In Play Console → Testing → Closed testing → check "Eligible for production" status
      If 14 days have not passed: wait. This task cannot complete until the gate clears.
    After gate clears:
      1. Play Console → Production → Apply for production access
      2. Google reviews the application (may take up to 7 days)
      3. After approval: confirm production rollout and run smoke test as in Case A

  Regardless of case: final step once Android is live:
    - Confirm Play Store URL resolves: https://play.google.com/store/apps/details?id=com.robvb.winny
    - Fresh install from Play Store (not test track): onboarding → first win → settings all work
  </how-to-verify>

  <resume-signal>Type "Android live" with the Play Store URL, or describe the gate status (days remaining, tester count) if still waiting, or rejection reason if rejected.</resume-signal>
