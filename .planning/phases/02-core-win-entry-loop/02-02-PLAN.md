  <action>
    Create `src/stores/useWinsStore.ts` with the exact content below.

    CRITICAL invariants:
    - Zustand v5: use `create<WinsState & WinsActions>()((set, get) => (...))` — note the double parentheses after `create<...>`. This is NOT a typo; it is required for v5 TypeScript inference (RESEARCH.md Section 1).
    - Do NOT use `zustand/middleware/persist` — SQLite is the persistence layer (RESEARCH.md Section 1 key decisions).
    - Do NOT call `insertWin(text, dateKey)` — `insertWin` takes ONLY `text`; it calls `toDateKey()` internally (Pitfall 5).
    - Import path for repositories uses `@/src/db/repositories/wins` (matches existing codebase `@/` alias).

    ```typescript
    import { create } from "zustand";
    import { useShallow } from "zustand/react/shallow";
    import {
      insertWin,
      getWins,
      getDistinctDateKeys,
    } from "@/src/db/repositories/wins";
    import { computeStreak, toDateKey } from "@/src/utils/dateUtils";
    import type { Win } from "@/src/db/schema";

    interface WinsState {
      wins: Win[];
      todayWins: Win[];
      streak: number;
      totalWins: number;
      isHydrated: boolean;
    }

    interface WinsActions {
      hydrate: () => Promise<void>;
      addWin: (text: string) => Promise<void>;
    }

    export const useWinsStore = create<WinsState & WinsActions>()(
      (set) => ({
        wins: [],
        todayWins: [],
        streak: 0,
        totalWins: 0,
        isHydrated: false,

        hydrate: async () => {
          const wins = await getWins();
          const dateKeys = await getDistinctDateKeys();
          const today = toDateKey();
          set({
            wins,
            todayWins: wins.filter((w) => w.date_key === today),
            streak: computeStreak(dateKeys),
            totalWins: wins.length,
            isHydrated: true,
          });
        },

        addWin: async (text: string) => {
          // insertWin handles UUID pk, date_key, logged_at internally (Pitfall 5)
          await insertWin(text);
          // Re-query DB as single source of truth (avoids optimistic update divergence)
          const wins = await getWins();
          const dateKeys = await getDistinctDateKeys();
          const today = toDateKey();
          set({
            wins,
            todayWins: wins.filter((w) => w.date_key === today),
            streak: computeStreak(dateKeys),
            totalWins: wins.length,
          });
        },
      })
    );

    // Individual selector hooks — one value per hook prevents unnecessary re-renders
    export const useTodayWins = () => useWinsStore((s) => s.todayWins);
    export const useStreak = () => useWinsStore((s) => s.streak);
    export const useTotalWins = () => useWinsStore((s) => s.totalWins);
    export const useIsHydrated = () => useWinsStore((s) => s.isHydrated);
    export const useAddWin = () => useWinsStore((s) => s.addWin);
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI → store.addWin | User-typed text enters `addWin(text)` which calls `insertWin(text)` — text length validation must happen at UI layer before this call |
| store → SQLite | `insertWin` runs a parameterized Drizzle ORM insert — no SQL injection possible via Drizzle's prepared statements |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Tampering | `addWin(text)` | mitigate | Text length guard (1–200 chars) enforced in WinInputArea component (Plan 03) before `addWin` is called; store itself does not need a second guard |
| T-02-02-02 | Denial of Service | Double-submit race | mitigate | `isAdding` state flag in WinInputArea (Plan 03) prevents second call before first resolves; Pitfall 8 pattern |
| T-02-02-03 | Information Disclosure | Win text in SQLite | accept | Local device storage; no network; no PII beyond user-authored text; V2 sync is additive |
</threat_model>
