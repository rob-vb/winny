## Interaction Contract

### Win Add Flow

1. User types in TextInput (focus on mount — `autoFocus={true}`).
2. User taps "Add" button OR presses keyboard return key.
3. Guard: if `inputText.trim().length === 0` or `isAdding`, do nothing.
4. Guard: if `inputText.length > 200`, do nothing (maxLength prevents this at UI level).
5. Set `isAdding = true`; disable Add button (`opacity-50`).
6. Call `addWin(text.trim())` — async write to SQLite + store re-hydrate.
7. Clear `inputText` to `""`.
8. Call `flatListRef.current?.scrollToOffset({ offset: 0, animated: true })`.
9. Do NOT call `TextInput.blur()` — keyboard stays open for next win.
10. Set `isAdding = false`; re-enable Add button.
11. New win item at index 0 receives `ZoomIn.duration(300)` entering animation.

### Keyboard Behavior

| Platform | Behavior | Implementation |
|----------|----------|---------------|
| iOS | Input pushed above keyboard | `KeyboardAvoidingView behavior="padding"` |
| Android | OS handles via adjustResize | `KeyboardAvoidingView behavior={undefined}` |
| Both | Keyboard stays open after add | Do NOT call `.blur()` after `addWin` |
| Both | Input auto-focused on screen mount | `autoFocus={true}` on TextInput |

### Empty State ↔ Populated State Transition

- Toggle is purely data-driven: `todayWins.length === 0` renders empty state; `> 0` renders FlatList.
- No animation on the transition between states — instant swap.
- `ExamplePrompts` and `WinInputArea` are rendered in both states — they do not animate in/out.
- On first add: FlatList appears, trophy image disappears. This happens synchronously as Zustand state updates.

### Hydration Loading State

- While `isHydrated === false`: render `StreakHeader` with placeholder text "Loading..." and null for the wins list region.
- `WinInputArea` may render immediately (no data dependency) — this allows the user to see the input is available.
- `isHydrated` becomes `true` within 20–100ms on typical devices. No spinner needed.

### Micro-Animation Specification

| Property | Value |
|----------|-------|
| Animation preset | `ZoomIn` from `react-native-reanimated` |
| Duration | 300ms |
| Target | `Animated.View` wrapping each `WinCard` |
| Trigger condition | `isNew === true` (only fires for the item at index 0 immediately after an add) |
| isNew tracking | `useRef<number>` stores previous `todayWins.length`; `isNew = index === 0 && todayWins.length > prevLengthRef.current` |
| Non-new items | `entering={undefined}` — no animation on scroll remount |

### Accessibility

| Element | Contract |
|---------|---------|
| Add button | `accessibilityLabel="Add win"` `accessibilityRole="button"` |
| TextInput | `accessibilityLabel="Win text input"` `accessibilityHint="Type your win for today, up to 200 characters"` |
| Trophy image | `accessibilityLabel="Winning Streak trophy"` |

## Example Prompts Contract

**Rotation algorithm:** `selectDailyPrompts(dateKey, count=3)` — pure function, deterministic by dateKey seed. Same 3 prompts all day. Different prompts each calendar day.

**Pool:** 40–50 curated short phrases. Generated by Claude during execution (Phase 2 Wave 1). Stored in `src/constants/examplePrompts.ts`. Format: plain short phrases, first-person, past tense. Example: "I helped a colleague today", "I finished something I'd been avoiding", "I showed up even when I didn't feel like it".

**Display format:** Each prompt prefixed with a bullet or subtle prefix character — no tappable affordance, no underline, no chevron.

**Width:** Prompts are truncated to 1 line with `numberOfLines={1} ellipsizeMode="tail"` to prevent wrapping disrupting the compact layout.
