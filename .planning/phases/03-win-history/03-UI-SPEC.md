## Spacing Scale

Inherited from Phase 1 (NativeWind v4 Tailwind spacing, multiples of 4 only).

| Token | px value | Tailwind class | Usage in Phase 3 |
|-------|----------|---------------|-----------------|
| xs | 4px | `p-1` / `gap-1` | Pill badge internal vertical padding; icon-to-label gap |
| sm | 8px | `p-2` / `gap-2` | Gap between date label and pill in section header; WinCard `mb-2` |
| md | 16px | `p-4` / `gap-4` | Screen horizontal padding; hero header horizontal padding; section header horizontal padding |
| lg | 24px | `p-6` / `gap-6` | Hero header vertical padding (top and bottom); section padding |
| xl | 32px | `p-8` / `gap-8` | Trophy image bottom margin in empty state |
| 2xl | 48px | `p-12` / `gap-12` | Empty state vertical centering offset |
| 3xl | 64px | `p-16` / `gap-16` | Reserved — not used in Phase 3 |

**Exceptions:**

- Section header vertical padding: `py-3` (12px) — slightly off standard scale; keeps header compact while providing a comfortable 44px+ touch target height when combined with font line height. Documented exception.
- Pill badge horizontal padding: `px-2` (8px). Pill badge vertical padding: `py-0.5` (2px). Chosen to keep the pill tight and readable at `text-xs`. Documented exception.
- Section list content bottom padding: `pb-4` (16px) — prevents last card from sitting flush at the screen bottom above the safe area. Standard practice.
- Chevron icon touch target: The entire section header row is the tappable surface (min height 44px via `py-3` + font). Do not restrict touch to the chevron icon alone (D-04).

## Screen Layout Contract

Phase 3 replaces `app/(tabs)/wins.tsx` entirely. The screen has two states: empty (zero wins ever) and populated (one or more wins exist).

### Top-Level Layout Structure (Populated State)

```
SafeAreaView (flex-1 bg-background)
  └── SectionList
        ├── ListHeaderComponent
        │     └── HistoryHeroHeader (totalWins, streak, trophy)
        ├── renderSectionHeader
        │     └── DateSectionHeader (date label, pill badge, chevron)  ← sticky
        └── renderItem
              └── WinCard (win, isNew={false})  OR null if section collapsed
```

### Top-Level Layout Structure (Empty State)

```
SafeAreaView (flex-1 bg-background)
  └── View (flex-1, items-center, justify-center, px-4)
        ├── Image: trophy.png (~120px wide)
        ├── Text: empty state heading
        └── Text: empty state subtext
```

### Loading / Hydration State

While `isHydrated === false` (store not yet ready): render `null` (blank screen matching `bg-background`). The hydration window is typically 20–100ms and is complete before the user navigates to this tab on normal launch. Do NOT call `hydrate()` again — the store is already hydrated by the Home screen at boot.

## Date Label Formatting Contract

The `formatDateKey(dateKey: string): string` utility lives in `src/utils/dateUtils.ts`.

```typescript
import { isToday, isYesterday, isSameYear, format } from 'date-fns';

export function formatDateKey(dateKey: string): string {
  // Noon anchor prevents DST edge-case misclassification
  const d = new Date(dateKey + 'T12:00:00');
  if (isToday(d)) return 'Today';
  if (isYesterday(d)) return 'Yesterday';
  if (isSameYear(d, new Date())) return format(d, 'EEE, MMM d'); // "Sat, May 9"
  return format(d, 'MMM d, yyyy');                               // "Dec 1, 2025"
}
```

**Critical:** Always use `dateKey + 'T12:00:00'` noon anchor. Never `new Date(dateKey)` directly — that parses as UTC midnight and produces off-by-one in negative UTC offset timezones.

## Interaction Contract

### Collapse / Expand Toggle

1. User taps anywhere on the `DateSectionHeader` row (the full-width `Pressable`).
2. `onToggle(date_key)` fires.
3. `collapsedSections` state updates: `{ ...prev, [date_key]: !prev[date_key] }`.
4. SectionList re-renders because `extraData` reference has changed.
5. `renderItem` returns `null` for all items in the collapsed section → items disappear.
6. `DateSectionHeader` receives updated `isCollapsed` prop → chevron `useEffect` fires → `withTiming(180, { duration: 200 })` runs → chevron rotates 180° over 200ms.
7. Tapping the same header again reverses: items reappear, chevron returns to 0° over 200ms.

**Multiple sections:** Each section's collapse state is independent. Collapsing one section does not affect others.

### Scroll Behavior

- SectionList is the scroll container; no surrounding ScrollView.
- Sticky section headers: current section header pins to top of viewport as user scrolls through that section's items; pushed off by the next section header.
- Hero header: scrolls off screen as user scrolls down into history. Not re-anchored.
- No scroll-to-top FAB in V1.

### Tab Tap (My Wins tab)

- Tapping the My Wins tab when already on it triggers the Expo Router default scroll-to-top behavior. This is acceptable default behavior — no custom override needed.
- Cold navigation to My Wins tab: screen renders with all sections expanded (initial `collapsedSections = {}`).
